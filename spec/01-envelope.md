# 01 — The envelope

Everything portable about a message travels in AMQP headers with an
`x-acemq-` prefix, so any library and any non-AceMQ consumer can read it. The
generated byte-level reference is [`fixtures/envelope-fixtures.json`](../fixtures/envelope-fixtures.json)
(written by `acemq-java-amqp`, carried byte-for-byte by the other four); the
cases here are the same contract checked live, on what a real publish put on a
real broker.

### AMQP-ENV-001 (MUST) The envelope headers and their types

Cases: ENV-001, ENV-002

| Header | AMQP type | Meaning |
|---|---|---|
| `x-acemq-id` | long string | the message identifier, a UUID unless the caller gave one |
| `x-acemq-type` | long string | the logical message type |
| `x-acemq-version` | integer | schema version |
| `x-acemq-correlation` | long string | business correlation, carried across hops |
| `x-acemq-causation` | long string | the id of the message that caused this one; absent when there is none |
| `x-acemq-attempt` | integer | delivery attempt, 1 on first publish |
| `x-acemq-first-seen` | integer | epoch milliseconds of the first publish |
| `x-acemq-origin` | long string | `{clientName}@{hostname}` of the publisher |
| `x-acemq-claim` | long string | claim-check URI; absent unless the payload was externalised |

An integer header MUST be written as an AMQP integer type, never as a string.

### AMQP-ENV-002 (MUST) The id is also the AMQP message-id

Cases: ENV-001, ENV-002

The `message_id` property equals `x-acemq-id`.

### AMQP-ENV-003 (MUST) Correlation defaults to the id

Cases: ENV-001

A publish with no correlation supplied carries `x-acemq-correlation` equal to
`x-acemq-id`.

### AMQP-ENV-004 (MUST) The attempt starts at one

Cases: ENV-001, ENV-002

### AMQP-ENV-005 (MUST) The version defaults to one

Cases: ENV-001

### AMQP-ENV-006 (MUST) The type defaults to the routing key

Cases: ENV-001

With no type supplied, `x-acemq-type` is the routing key the message was
published under, and the literal `message` when that routing key is empty.

### AMQP-ENV-007 (MUST) First-seen is set once, in epoch milliseconds

Cases: ENV-001, ENV-002

Set on the first publish, and carried unchanged by every hop after it.

### AMQP-ENV-008 (MUST) Origin is `{clientName}@{hostname}`

Cases: ENV-001, ENV-002

### AMQP-ENV-009 (MUST) Causation is absent unless supplied

Cases: ENV-001

Not an empty string: absent.

### AMQP-ENV-010 (MUST) Caller fields and headers reach the wire unchanged

Cases: ENV-002

An id, type, version, correlation and causation the caller supplies are
written as given, and so is every caller header outside the `x-acemq-`
namespace.

Cases: ENV-001, ENV-002

### AMQP-ENV-012 (MUST) Messages are persistent by default

Cases: ENV-001, ENV-002

`delivery_mode` is 2 unless the caller asked for a transient publish.

### AMQP-ENV-013 (MUST) A replayed message carries the replay audit headers

Cases: none yet

`acemq-replay-count`, `acemq-replayed-at` (ISO-8601 UTC, millisecond
precision) and `acemq-replayed-from` (the queue it was taken from), as in the
`replayed` fixture.
