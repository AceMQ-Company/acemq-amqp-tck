# AceMQ AMQP TCK

The behavioural specification of the AceMQ AMQP libraries, and the
compatibility kit every one of them runs:
[Java](https://github.com/AceMQ-Company/acemq-java-amqp),
[Python](https://github.com/AceMQ-Company/acemq-python-amqp),
[Ruby](https://github.com/AceMQ-Company/acemq-ruby-amqp),
[.NET](https://github.com/AceMQ-Company/acemq-dotnet-amqp) and
[Go](https://github.com/AceMQ-Company/acemq-go-amqp).

Five implementations of one contract are one product only while they behave
the same. This repository says what "the same" is, and turns every difference
into a failing build instead of something found by reading code.

| | |
|---|---|
| [`spec/`](spec) | numbered requirements (`AMQP-SCHED-001`, MUST/SHOULD) |
| [`cases/`](cases) | language-neutral test cases, one JSON file each |

| [`fixtures/`](fixtures) | the byte-level cross-language fixtures, as generated by the Java library |

| [`ROADMAP.md`](ROADMAP.md) | requirements without a case yet |

## How it runs

Each library carries a small **driver** under its test sources that performs
TCK operations through its real API. The runner starts the driver, arranges a
real RabbitMQ through the management API, plays any misbehaving peer itself,
and checks the outcome on the broker. Drivers assert nothing, so five
libraries cannot pass five different ways.

In a library's CI:

```yaml
  tck:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      # ... set up the toolchain and build the driver ...
      - uses: AceMQ-Company/acemq-amqp-tck@v0.3.0
        with:
          driver: python tests/tck/driver.py
```

The `@v0.3.0` is the library's pin: the version of the contract it passes.

Locally, against any RabbitMQ with the management plugin:

```bash
ACEMQ_TCK_AMQP_URL=amqp://guest:guest@localhost:5672/ \
  python3 runner/tck.py --management http://guest:guest@localhost:15672 \
  --driver "python ../acemq-python-amqp/tests/tck/driver.py" -v
```

`--only RETRY` runs the cases whose id matches; `--validate` checks the cases
against the spec; `--self-test` checks the matcher.
